## 🛡️ القواعد الذهبية (غير قابلة للتفاوض)

### ✅ مسموح لك أن تفعل
- ✅ إنشاء/تعديل ملفات CSS داخل `assets/css/shield/` فقط.
- ✅ إنشاء/تعديل ملفات JS داخل `assets/js/shield/` فقط.
- ✅ إنشاء ملفات HTML markup مُضمَّنة داخل `includes/` (للعرض البحت).
- ✅ إضافة classes جديدة على عناصر HTML الموجودة.
- ✅ تغليف HTML موجود بـ `<div>` wrapper إضافي.
- ✅ إضافة سطرين على `config_settings.php`: `ui_engine`, `ui_theme`.
- ✅ إضافة استدعاءات `<link>` / `<script>` مشروطة داخل `core.php → head()`.

### ❌ ممنوع منعاً باتاً
- ❌ لمس أي ملف داخل `modules/` (هذه عمليات الحماية الفعلية).
- ❌ تعديل أو حذف أي استعلام SQL في أي ملف.
- ❌ تغيير اسم أي متغير PHP أو دالة موجودة.
- ❌ تعديل منطق التحقق، الحظر، الجلسات، أو معالجة الطلبات.
- ❌ إنشاء مجلدات `lib/` أو `api/` أو نقل أي منطق إليها.
- ❌ تعديل `config.php` (الاتصال بقاعدة البيانات).
- ❌ حذف classes من AdminLTE / Bootstrap — فقط أضف فوقها.
- ❌ استبدال Chart.js / DataTables / jQuery — اضبط إعداداتها فقط.
- ❌ تغيير schema قاعدة البيانات أو إنشاء جداول.
- ❌ كتابة وسم `<html>` جديد داخل `head()` (يكسر بنية الصفحة).

### 🔄 الاختبار الذهني قبل أي تعديل (3 أسئلة)
قبل حفظ أي تغيير على ملف PHP موجود، اسأل نفسك:

1. **هل هذا التعديل بصري بحت** (CSS/HTML/JS فقط)؟
2. **لو غيّر المستخدم `ui_engine` إلى `legacy` الآن، هل سيعمل النظام بنفس السلوك تماماً؟**
3. **هل أي متغير أو دالة تم تغيير اسمها أو حذفها؟**

إن كانت إجابة (1) لا، أو (2) لا، أو (3) نعم — **توقف فوراً واطلب توضيحاً**.

## 🧱 المعايير التقنية الإجبارية

### 1. CSS — استخدام Tokens فقط
**ممنوع** كتابة قيم لونية أو مساحات صلبة (hardcoded). كل قيمة تأتي من Token:

```css
/* ❌ خطأ */
.my-card {
  background: #1A2236;
  padding: 16px;
  border-radius: 8px;
  color: #00B8E6;
}

/* ✅ صحيح */
.my-card {
  background: var(--color-surface-2);
  padding: var(--space-4);
  border-radius: var(--radius-md);
  color: var(--color-brand-primary);
}
```

راجع `02-design-tokens.md` للقائمة الكاملة.

### 2. تسميات الكلاسات — BEM-Lite بـ prefix
كل class جديد يبدأ بـ `shield-`:

```css
.shield-card { }                    /* Block */
.shield-card__header { }            /* Element */
.shield-card--elevated { }          /* Modifier */
.shield-kpi-card { }                /* Component */
```

**ممنوع:**
- ❌ تسميات عامة بدون prefix مثل `.card`, `.btn-blue`, `.my-table`.
- ❌ تعديل classes موجودة من Bootstrap/AdminLTE مباشرة.
- ❌ استخدام `!important` إلا في ملف `overrides/` بمبرر مكتوب.

### 3. RTL أولاً
كل CSS يُكتب لـ العربية:
- استخدم `margin-inline-start` بدل `margin-left`.
- استخدم `padding-inline-end` بدل `padding-right`.
- خصائص اتجاه الـ flex / grid مع مراعاة RTL.

### 4. الخطوط
- النصوص: `font-family: var(--font-sans)` (IBM Plex Sans Arabic).
- الأرقام/IPs/الكود/التواريخ: `font-family: var(--font-mono)` + `font-variant-numeric: tabular-nums`.

### 5. الأيقونات
استخدم **Lucide Icons** للكود الجديد:
```html
<i data-lucide="shield-check" class="icon icon-md"></i>
```
لا تستبدل FontAwesome في الكود القديم — اتركه كما هو.

### 6. PHP — للعرض فقط
أي PHP في ملفات `includes/` يجب أن يكون:
- ✅ echo/print لـ HTML.
- ✅ شروط بسيطة على متغيرات موجودة (`isset`, `empty`, `==`).
- ✅ حلقات `foreach` على مصفوفات موجودة.
- ❌ **ممنوع** أي `mysqli_query`, `$mysqli->prepare`, أو أي اتصال DB.
- ❌ **ممنوع** أي `$_POST`/`$_GET`/`$_SESSION` writes.
- ❌ **ممنوع** include لملفات خارج `includes/`.

## 🔧 منهجية التنفيذ (Workflow)

اتبع هذه الخطوات بهذا الترتيب لكل مهمة، بدون استثناء:

### الخطوة 1 — الفهم
1. اقرأ المهمة في النهاية بعناية.
2. اقرأ `00-README.md` و `07-implementation-roadmap.md` (القواعد الذهبية).
3. حدد أي وثائق أخرى تحتاجها بناءً على نوع المهمة.
4. **إن كان شيء غامضاً، اسأل قبل أن تكتب أي كود.**

### الخطوة 2 — الفحص
1. اطلب من المستخدم أي ملفات مصدر تحتاجها (مثلاً: محتوى `core.php` الحالي إن كنت ستضيف فيه استدعاءات).
2. لا تخمّن محتوى الملفات الموجودة — اطلب رؤيتها أولاً.
3. حدد الملفات التي ستنشئها/تعدلها بدقة.

### الخطوة 3 — الخطة (Plan)
قبل كتابة أي كود، أرسل خطة قصيرة بهذا الشكل:

```
## خطة التنفيذ
**الهدف:** [وصف بسطر واحد]

**الملفات الجديدة:**
- assets/css/shield/components/_xxx.css (إنشاء)
- includes/shield-yyy.php (إنشاء)

**الملفات المعدلة:**
- core.php (إضافة سطرين فقط داخل head() — لا حذف ولا تعديل)

**Tokens المستخدمة:** --color-surface-2, --space-4, --radius-md
**Components مرجعية من 04:** shield-card, shield-table

**المخرج النهائي:** [وصف ما سيراه المستخدم]

**اختبار سلامة الباك-إند:**
☐ لا تعديل في modules/
☐ لا SQL تم لمسه  
☐ لا متغير PHP غير اسمه
☐ التبديل لـ ui_engine=legacy يعيد كل شيء كما كان

هل تريد المتابعة؟
```

انتظر موافقة المستخدم قبل التنفيذ.

### الخطوة 4 — التنفيذ
1. أنشئ الملفات الجديدة كاملةً مع تعليقات واضحة.
2. **عدّل الملفات الموجودة بأقل قدر ممكن** — أضف، لا تحذف.
3. كل ملف جديد يبدأ بـ header comment يوضح:
   ```css
   /**
    * shield/components/_kpi-card.css
    * KPI Card Component
    * Reference: docs/04-component-library.md § 3.2
    * Depends on: _tokens.css
    */
   ```

### الخطوة 5 — التسليم
في نهاية كل مهمة، قدّم:

```
## ملخص التنفيذ
**ما تم إنشاؤه:** [قائمة]
**ما تم تعديله:** [قائمة + سطور بالتحديد]
**كيفية التجربة محلياً:** [خطوات]
**كيفية التراجع:** غيّر `$settings['ui_engine']` إلى `'legacy'`.

**اختبارات يدوية موصى بها:**
1. ...
2. ...

**ملاحظات/قيود:** [إن وُجدت]
```

## 🎁 إضافات اختيارية لكل برومبت

عند إرسال مهمة جديدة، يمكنك إضافة بعض هذه التفاصيل لتسريع العمل:

### مرفقات مفيدة
- محتوى ملف PHP الحالي الذي ستعدله (أهم شيء).
- لقطة شاشة من الواجهة الحالية.
- لقطة شاشة من تصميم تستلهم منه.
- قائمة المتغيرات الموجودة في الصفحة (أسماء PHP variables).

### تحديد النطاق
- **مدة متوقعة:** "أريد إنجازها في جلسة واحدة" / "خذ وقتك"
- **نطاق محدد:** "صفحة Dashboard فقط" / "كل صفحات Logs"
- **أولوية:** "الموبايل أولاً" / "الديسكتوب فقط الآن"

### مثال على مهمة محددة
```
## المهمة الحالية
أريد تطبيق التصميم الجديد على بطاقات KPI في صفحة dashboard.php.

**المرفقات:**
- محتوى dashboard.php الحالي (انظر آخر الرسالة)
- المتغيرات المتاحة: $total_blocked, $threats_today, $bots_blocked, $spam_blocked

**النطاق:** بطاقات KPI الأربعة فقط (لا تلمس الـ Charts ولا الجدول الآن).
**Sparklines:** اتركها لمهمة قادمة.
**ابدأ بإرسال خطة التنفيذ.**
```

## 🧭 نصائح لاستخدام البرومبت

1. **لا تختصر القواعد الذهبية.** هي العمود الفقري لحماية مشروعك.
2. **في كل جلسة جديدة:** أرفق مجلد `nn/` كاملاً + هذا البرومبت + المهمة.
3. **إن كان الـ AI يستخدم سياقاً محدوداً**، اطلب منه قراءة `00-README.md` و `07` فقط ثم سؤالك أي وثيقة أخرى يحتاجها.
4. **حافظ على Git commits صغيرة.** كل مهمة = commit واحد على الأقل.
5. **اختبر بعد كل مرحلة بـ `ui_engine = legacy`** للتأكد أن الموقع يعود للوضع الأصلي تماماً — هذا اختبار سلامة ممتاز.
